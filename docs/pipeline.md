# How the translation pipeline works

A plain-language walkthrough of what happens when a TEI file is translated, written for the team. For the decisions behind each rule see `docs/tag_decisions.md` and `config/policy.yaml`; for measurements see `docs/spanwise_cost.md` and `docs/engine_comparison.md`.

## The idea in one sentence

Pull the Greek text out of the XML, give the MT model **plain sentences only** (it never sees a tag), then put every tag back into the English by rules. The XML structure is never generated by a model; it is only copied or moved.

## What happens to a file

Entry point: `translate_document()` in `src/tei_translate/pipeline/document.py`. The CLI (`python -m tei_translate translate IN.xml`) is a thin layer over it; the Gradio app will be too.

1. **Load the settings.**
   - `config/pairs/grc-en.yaml`: language pair, engine (default `madlad-3b`), placement mode (default `hybrid`), aligner, schema.
   - `config/policy.yaml`: what to do with each tag.
2. **Parse the file and keep an untouched copy.** The copy is used at the end to check that nothing broke.
3. **Classify every element inside `<text>`.** The `<teiHeader>` is left alone. The policy gives each element:
   - a **role**:
     - *block*: a self-contained piece of text, such as `<p>`, `<l>` or `<head>`
     - *inline*: something inside the running text, such as `<persName>`, `<foreign>` or `<q>`
     - *container*: holds blocks, such as `<div>`
     - *empty*: a marker with no text, such as `<pb/>` or `<milestone/>` (detected automatically: no text, no children)
   - a **treatment**:
     - *translate*
     - *keep*: copy the text as it is
     - *transliterate*: write the Greek in Latin letters (`<speaker>`, `<label>`)
     - *keep-subtree*: copy the element and everything inside it (`<note>`)

   The code only knows roles and treatments. Tag names appear only in `policy.yaml`.
4. **Translate the blocks** (details below). Most blocks use the *hybrid* method. A block it cannot handle falls back to the simpler *span-wise* method.
5. **Finish the document:**
   - change `xml:lang="grc"` to `"en"` wherever text was translated (not inside kept elements)
   - add a `<respStmt>` to the header that names the engine
6. **Validate** the output against the untouched copy (`pipeline/validate.py`):
   - the XML is well-formed
   - every element is still there, under the same parent
   - `@n` / `@xml:id` numbering and the order of markers are unchanged
   - kept elements are byte-identical
   - the header is unchanged (apart from the new `respStmt`)
   - the file is valid TEI (`tei_all`), allowing errors the source file already had

   The result is a **report**: which rules fired, how each tag was placed, why any block went span-wise, and PASS/FAIL for each check.

## How one block is translated (hybrid mode)

Code: `pipeline/hybrid.py`, which calls `detag.py`, `sentences.py` and `placement.py`.

A block goes hybrid if its treatment is *translate* and it has no other blocks inside it. A toy paragraph:

```xml
<p>ὁ <persName>Σωκράτης</persName> ἔλεγεν. ἡ ψυχή <pb n="5"/>ἀθάνατός ἐστιν.<note>cf. Phd.</note></p>
```

### Step 1: Remove the tags and remember where they were (`detag.py`)

The result is plain text plus a list of *anchors*:

```
ὁ Σωκράτης ἔλεγεν. ἡ ψυχή ἀθάνατός ἐστιν.
  └persName─┘              ↑pb          ↑note
```

There are three kinds of anchor:

| Kind | What it is | Example | What is recorded |
|---|---|---|---|
| **wrap** | an element whose text is translated with the rest | `persName`, `q` | where it starts and ends in the text |
| **point** | something with no translatable text: an empty marker, a kept subtree (its text leaves the sentence), a comment, a `mt_input: remove` element | `pb`, `milestone`, `note`, `bibl` | its position only |
| **fixed** | a keep/transliterate element | `label`, `foreign` | where it starts and ends |

The model still sees the Greek of a *fixed* element, so the sentence reads naturally. Afterwards, the English the model wrote for it is replaced by the element itself, with its own content (transliterated if that is its treatment).

### Step 2: Split into sentences (`sentences.py`)

Splits at `. ; ! ?` and the Greek question mark (U+037E):

1. ὁ Σωκράτης ἔλεγεν.
2. ἡ ψυχή ἀθάνατός ἐστιν.

### Step 3: Translate

All sentences of the whole document go to the engine in **one batch**, one sentence per segment. Inside the engine, long sentences are split further (at `, : ·`, then at word boundaries) and the pieces are joined again. Sentences without letters (numbers, punctuation) are copied, not translated.

1. Socrates said.
2. The soul is immortal.

### Step 4: Align words, only where needed

- A tag that covers whole sentences, or sits between two sentences, needs no alignment: Greek sentence 1 is English sentence 1.
- A tag that starts or ends *inside* a sentence does. Those sentence pairs go to the word aligner in one batch (default UGARIT, a Greek–English aligner; `monotone` for tests).

Here `persName` and `pb` are inside sentences, so the aligner links Σωκράτης↔Socrates, ψυχή↔soul, ἀθάνατός↔immortal, and so on.

### Step 5: Put the tags back (`placement.py`)

Each tag has a strategy set in the `params` of its rule in `policy.yaml`:

| Tags | Strategy |
|---|---|
| wrap elements (`persName`, `q`, ...) | wrap the smallest stretch of English covering every word aligned to its Greek |
| `pb`, `lb` (`placement: boundary`) | move to the nearer edge of its sentence; an exact spot inside a sentence means little after translation |
| `note`, `bibl`, `gap` (`align`, `anchor: left`) | right after the English of the Greek word before it |
| `milestone` (`align`, `anchor: right`) | right before the English of the next Greek word |
| `milestone[unit=para]` | sentence boundary (97% already sit at sentence ends) |

Some general rules:
- Points between sentences stay between sentences.
- Outer tags are placed before inner ones.
- Markers of the same kind (e.g. two `pb`s) keep their order.
- A point with spaces on both sides keeps them.

Result:

```xml
<p><persName>Socrates</persName> said. <pb n="5"/>The soul is immortal.<note>cf. Phd.</note></p>
```

### Step 6: Fall back if placement fails

If a tag cannot be placed sensibly, the block is not forced. The reasons are counted in the report as `<tag>:<reason>`:

- `unaligned`: no word of the element aligned
- `too-wide`: the aligned English span is more than 2× the Greek words + 3
- `overlap`: two sibling tags would cross
- `outside-parent`: a tag would end up outside the element it belongs in
- `out-of-order`: markers of the same kind would come out swapped

What happens then is the rule's `fallback` param: `spanwise` (the whole block goes span-wise; default for inline tags), `boundary` (points go to a sentence edge) or `sentence` (wrap whole sentences). Blocks that contain other blocks (e.g. `<l>` inside `<p>`) always go span-wise, reported as `contains-blocks`.

## Span-wise mode, the fallback

Code: `pipeline/spans.py` and `apply_spans()` in `document.py`. Also selectable for a whole file with `--placement spanwise`.

Every piece of text is translated **where it sits**, between the tags, and nothing moves:
- text inside an element gets that element's treatment
- text after an element (its *tail*) gets the parent's treatment
- when inline elements are nested, the more protective treatment wins (keep > transliterate > translate)

It never breaks the structure, but it cuts sentences. In the example the model would get `ὁ`, `Σωκράτης`, `ἔλεγεν. ἡ ψυχή` and `ἀθάνατός ἐστιν.` as separate pieces, and the English comes out choppy. That is why hybrid is the default.

## Where things stand

- **Corpus check:** all 626 Greek Perseus files, run with the identity engine and the exact `monotone` aligner: every check passes. 217,573 blocks went hybrid and 2,928 span-wise (2,862 because they contain blocks, ~64 from tags inside words).
- **Quality:** on 16 prose passages with mid-sentence cuts, chrF is hybrid 21.9, span-wise 21.6, whole passage 21.7. The differences are within noise; what hybrid gains is readable sentences rather than a higher score.
- **Not done yet:** a hand-tagged gold set to measure how accurately hybrid places tags (`metrics.scores.tag_accuracy`).

## Module map

| File | Job |
|---|---|
| `pipeline/document.py` | entry point; runs the steps above, `apply_spans`, `xml:lang`, `respStmt` |
| `pipeline/policy.py` | reads `policy.yaml`, classifies elements into role + treatment |
| `pipeline/spans.py` | walks `<text>`, collects text pieces (spans), writes translations back |
| `pipeline/hybrid.py` | picks hybrid blocks, batches translation and alignment, hands the rest back |
| `pipeline/detag.py` | block → plain text + anchors |
| `pipeline/sentences.py` | sentence splitting |
| `pipeline/placement.py` | puts anchors into the English, rebuilds the block |
| `pipeline/transliterate.py` | Greek → Latin letters |
| `pipeline/validate.py` | the output checks and the TEI schema check |
| `engines/` | MT engines (`identity`, `tag`, Opus-MT, MADLAD, NLLB pivot chain) |
| `align/` | word aligners (`monotone`, UGARIT, ...) |

## Try it

```powershell
python -m tei_translate translate tests/fixtures/tei/handmade.xml --engine tag --aligner monotone
```

The `tag` engine wraps each segment as `[EN:...]`, so the output shows exactly what the model received. The report is printed to the terminal; the file goes to `outputs/`.
